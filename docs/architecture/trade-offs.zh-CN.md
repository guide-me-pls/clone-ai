# 架构取舍

[English](trade-offs.md) · **简体中文**

只有把理由写下来，一个决定才算真正稳定。每条记录都说明决定了什么、依据是什么，以及在
什么条件下后来者应当推翻它。

## 2026-11-05 — 提示词溯源 = 内容寻址文件 + 一条 Journal 事件

**决定。** 每个主 Agent 回合记录 charter 版本、编译后的情境简报、实际注册的工具表、
模型 id 与推理强度。完整材料写入 `<clone home>/prompt-snapshots/<materialHash>.json`；
Journal 追加一条 `main_agent.prompt_snapshot` 事件，携带各项哈希、定位符，以及桌面回合
的 turn id。

**依据。** 改动之前，Journal 能说明 Agent 做了什么、召回什么，却说不清它被告知了什么：
`MAIN_AGENT_CHARTER` 是常量，情境简报只存在于单个会话的内存里，工具表只存在于 Pi 会话
内部。因此失败的一轮无法归因到某一版提示词，两次"改进"也无法与基线比较。Journal 本来
就是 append-only 的真相（[`state-projector.ts`](../../src/state/state-projector.ts) 从
它重建状态），所以溯源应当放在这里，而不是另开一份日志。

**推翻条件。** 如果 Journal 不再是回合级遥测的合适归宿（例如保留策略要求 Run 与回合按
不同周期过期），就把事件迁移到以同一个 `materialHash` 为键的专用存储；哈希方案与文件
布局不依赖 Journal。

## 2026-11-05 — 工具溯源在注册时捕获，而不是维护一份清单

**决定。** `createKernelToolsExtension` 在注册每个工具的同一时刻通过 `onRegister` 回调
上报它。哈希覆盖模型真正收到的名称、描述与参数结构。

**依据。** 手工维护的工具名清单是第二个真相来源，第一次重命名或新增工具时就会悄悄漂移
——而这正是溯源要暴露的不可见变更。回调看到的是被注册的对象本身，因此不可能与会话不一致。

**推翻条件。** 如果工具可以在 `createKernelToolsExtension` 之外注册（第二个扩展工厂，
或 MCP 托管的工具），注册入口就不再覆盖完整工具表；届时快照必须从会话读取工具列表，
而不是依赖回调。

## 2026-11-05 — 回归门禁离线、逐用例、只衡量行为

**决定。** `npm run gate` 对 held-out 夹具重新运行证据验证与权限策略，用所有者标注
校准审计记录，并把每个用例与记录的基线比较。它不调用模型，是 CI 的必需步骤。

**依据。** 本仓库的保证位于模型周围的规则：完成来自证据，权限来自 Scope，所有者判定
来自 `audit.labeled`。这些层是确定性的，因此零成本门禁可以在每次提交时覆盖它们。
依赖 Provider 的评估，恰恰会在 CI 承压时被跳过。

**推翻条件。** 如果录制的轨迹 cassette 能在无网络环境下回放，就在确定性套件旁边增加
轨迹套件。逐用例基线对判断层始终有效。

## 2026-11-05 — 判定变化即使是改进也会让门禁失败

**决定。** `baseline.json` 记录每个用例当前的结果；任何差异——通过变失败或失败变通过
——都会失败，直到在同一次变更中运行 `--write-baseline`。

**依据。** 未经 diff 审查就到达的改进，与一个恰好在夹具集上看起来更好的回退无法区分。
强制更新基线，使审查者必须看到行为差异及其理由。

**推翻条件。** 如果基线变动开始主导审查成本，就按套件拆分，或为每个用例增加明确的
意图说明；不要改成静默自动更新。

## 2026-11-04 —— 移除哈希 n-gram"语义"召回项

**决定：** 移除。`MdMemoryStore.recall` 保留 bigram 比例、IDF 加权余弦、偏好先验与虚词下限。

**备选：** 保留在 `CLONE_AI_RECALL_SEMANTIC` 开关之后；换成真实 embedding 服务。

**为什么输。** 在 LongMemEval-s（470 道计分题、完整干草堆、maxResults=10）上做消融：

| 指标 | 有语义项 | 无语义项 |
| --- | --- | --- |
| any@1 | 77.9% | 76.6% |
| any@5 | 91.3% | 91.7% |
| any@10 | 95.5% | 94.9% |
| ndcg@10 | 82.0% | 81.5% |
| 上下文命中率 | 92.6% | 92.8% |

差值方向不一致，且在 n=470 时处于噪声范围内。一个无法证明有帮助的排序项，就是每次查询的纯成本
（每个候选多一次 SQL 取数、一张 2048 bucket 的表、约 40 行哈希代码）。

**放弃了什么。** 它本来想覆盖的场景——不共享任何精确词项的改写，例如"周五要交周报了"对
"每周五提交工作汇报"——不再被覆盖。不过在基准上它也从未被证明有效。

**可推翻条件。** 满足任一条：

- 出现真实的 embedding 端点（本地模型或网关能力），并在偏好题切分上胜过词法路径，而偏好题正是
  弱项：any@1 20.0%、any@10 70.0%；
- 出现结构上就不可能有精确词项重叠的产品问题类型（跨语言、大量缩写）；
- 在更大样本（LongMemEval-m）上重跑，差值符号反转。

## 2026-11-04 —— 保留 IDF 加权余弦项

**决定：** 保留在 `recall` 中。

**为什么赢。** 它不会引入任何不共享词项的记忆，最坏情况只是重排已经匹配上的记忆；同一次改动中加入的
虚词下限消除了它真正的失效模式（单个 "the" 就能通过 0.2 比例下限）。

**放弃了什么。** 每次召回、每个候选多一次 SQL 查询。

**可推翻条件。** 值得单独重测；若同样没有收益，按与语义项相同的标准移除。

**状态：** 目前是推测——尚未单独测量。

## 2026-11-04 —— 记忆推入 Main Agent 的 Prompt，而不是只留给拉取

**决定：** 每个回合由 `before_agent_start` 把匹配的记忆重新编译进 System Prompt。

**备选：** 只保留 `recall_memory` 工具路径；改为注入一条 user 角色消息。

**为什么赢。** 只拉不推意味着所有者批准过的记忆仍可能被当作不存在。走 System Prompt 复用了 Worker
已有的 1200 字符 / 6 条边界，且不改动对话历史（注入 user 消息会出现在对话记录与 `readConversation` 中）。

**放弃了什么。** 每回合一次召回（短生命周期 SQLite 句柄）；System Prompt 逐回合变化，削弱 Prompt 缓存。

**可推翻条件。** 若每回合延迟变得明显，或 Prompt 缓存节省的收益压过推送准确度。

## 2026-11-05 —— 取代上一条：对话提炼默认走廉价本地过滤

**决定：** `CLONE_AI_MEMORY_MINING` 现在是三档开关。未设置 = `filtered`：回合里含"持久陈述信号"时
才提炼（`src/memory/mining-policy.ts`）；`off` 同时关闭对话与任务提炼；`all` 每轮都提炼。任务提炼
除非处于 `all`，仍使用确定性 Worker。

**为什么改变上一条。** "显式开启"意味着个人 Agent 最需要的能力——无需被要求也能学习——开箱即关闭。
过滤器在本地运行、不产生模型调用，且宁可多提炼：漏掉一条陈述就是一条永远学不到的记忆，多一次调用只是几分钱。

**放弃了什么。** 没有信号的回合永不被提炼，因此一条陈述得很直白却不含任何匹配模式的记忆可能被漏掉。
`all` 是逃生门。

**可推翻条件。** 若实践中发现过滤器的漏检明显，就扩充信号列表，或把 `all` 设为默认。

## 2026-11-04 —— 对话提炼默认关闭（`CLONE_AI_MEMORY_MINING=1`）

**决定：** 与任务提炼一致，默认关闭。

**为什么赢。** 每个所有者回合一次模型调用。默认开启会把预算花在没产生值得记住内容的对话上。

**放弃了什么。** 开箱即用时，分身不会从对话中学习——这是与陪伴类产品最大的功能差距。

**可推翻条件。** 一旦有廉价或启发式的前置过滤能排除明显不含持久陈述的回合，提炼器即可默认开启。

## 2026-11-04 —— 失败聚类的教训通过 author 写入，而非提炼候选

**决定：** 同一失败签名出现 3 个以上 Run 时，经所有者批准通过 `MemoryGovernance.author()` 写入一条
`procedure` 记忆，而不是作为提炼候选。

**为什么赢。** 提炼候选只能引用自己 Run 的证据；聚类横跨多个 Run，没有单个 Run 能为其作证。所有者的批准
就是证据。

**放弃了什么。** 教训文本是模板拼出来的（类别、次数、签名、目录建议），而不是模型撰写。

**可推翻条件。** 若教训质量比引用纯度更重要，可允许带显式证据集的跨 Run 候选。

## 2026-11-04 —— 原生 Worker 靠环境变量开启，而非默认

**决定：** `CLONE_AI_NATIVE_MODEL` + `CLONE_AI_NATIVE_BASE_URL` 显式开启；否则 Registry 继续使用
沙箱化的 CLI Worker。

**备选：** 作为默认；总是注册但在派发时失败。

**为什么赢。** CLI Worker 有 OS 强制边界；原生 Worker 的边界由我们自己的代码保证。在它积累生产里程之前，
更安全的默认应当是有沙箱的那一个。

**放弃了什么。** 需要理解两种 Worker；原生路径尚未在大规模下验证。

**可推翻条件。** 原生 Worker 跑过真实所有者任务且没有边界回归后，可成为非编码任务的默认。

## 2026-11-04 —— 归档而不是删除

**决定：** 过期、闲置、淘汰都只归档，不销毁。

**为什么赢。** `memory.restored` 使每个决定都可回滚，Journal 也因此诚实地记录了分身曾知道什么。

**放弃了什么。** 原则上磁盘占用无上限。

**可推翻条件。** 增加"归档超过 N 年的记忆清理"，需所有者明确同意并记录原因。

## 2026-11-04 —— 90 天寿命与 90 天闲置

**决定：** 提升的记忆默认 90 天过期；任何活跃记忆 90 天未被使用即归档。

**为什么赢。** 90 天对应一个项目、一个工作周期或一个学期——所有者本人的说法。

**放弃了什么。** 一条仍然为真、只是 90 天内没被召回的事实会从召回中消失。可恢复，但需要所有者注意到。

**可推翻条件。** 若改进环路的使用数据显示被恢复的记忆其实仍有用，就延长窗口或豁免手写记忆。

**状态：** 90 天这个数字来自所有者的描述，是推测值，未测量。

## 2026-11-04 —— 所有者标签高于系统验证

**决定：** 结局归因中以 `audit.labeled` 判定好坏，系统验证作为兜底。

**为什么赢。** 标签是评估用来对照系统的真值。两者不一致时，按定义系统是错的。

**放弃了什么。** 一次草率的标签会污染该 Run 暴露过的每条记忆的归因。

**可推翻条件。** 若标签被证明噪声大，对已完成 Run 的 `fail` 标签要求附注或二次确认。

## 2026-11-04 —— 改进建议是确定性的，且待决上限 10 条

**决定：** 建议 id 由依据推导（`retire:<id>@<bucket>`），同时最多 10 条待决。

**为什么赢。** 每次扫描重算不能产生重复；建议泛滥会训练所有者盲目通过，等于废掉门禁。

**放弃了什么。** 一条真正新的建议可能被推迟到旧建议被决定之后。

**状态：** bucket 大小与上限 10 都是推测值，尚未调参。
