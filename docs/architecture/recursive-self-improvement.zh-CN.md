# 递归自我改进（RSI）设计

[English](recursive-self-improvement.md) · **简体中文**

状态：L0（记忆）环路已实现；聚类目前只用失败签名；基准门禁和取代（§5.4）尚未实现。
见末尾“实现”一节。

## 1. 目标与非目标

**目标。** 让分身在所有者反复出现的工作上持续、可度量地变好，且每一次改进都可见、可回滚、
由所有者批准。

**非目标**（每条附理由）：

- *不自我修改代码、提示词、授权策略或沙箱规则。* Kernel 的保证（审批、路径网关、验证）之所以
  可信，正因为被改进的对象改不到它们。若环路能改，一条坏教训就能替自己扩权。
- *不做无人值守的提升。* 提炼出的文本来自 Worker 输出，属于不可信输入（上下文构建器已按此对待）。
  所有者审核是唯一不依赖提炼器正确与否的控制点。
- *不宣称因果。* Run 数量少、任务各异，下面的度量只是观察性的：能排序、能建议，不能证明。

## 2. 环路

```
观察 -> 诊断 -> 提案 -> 门禁 -> 应用 -> 度量 -> 强化 / 淘汰
 ^                                                    |
 +----------------------------------------------------+
```

| 阶段 | 输入 | 输出 | 现状 |
| --- | --- | --- | --- |
| 观察 | Journal、`audit.labeled`、坏案例日志 | 每个 Run 的结局记录 | 部分有（`projectRunAudits`） |
| 诊断 | 失败 Run、`FailureReport.signature` | 反复出现的失败聚类 | 有 signature，无聚类 |
| 提案 | 一个聚类或单次失败 | 教训候选或目录建议 | 仅单次失败教训 |
| 门禁 | 候选 | 所有者决定、PII 扫描、证据校验 | 有（`MemoryGovernance`） |
| 应用 | 已批准的教训 | 带默认过期的活跃记忆 | 有，但未设默认过期 |
| 度量 | 召回记录 × 结局 | 每条记忆的有用性统计 | 无 |
| 强化 / 淘汰 | 有用性统计 | 置信度调整、归档建议 | 无 |

## 3. 允许改变什么（变更面）

| 层级 | 对象 | 谁批准 | 为什么放在这一层 |
| --- | --- | --- | --- |
| L0 | 记忆教训（`procedure`、`preference`） | 所有者，逐条 | 已受治理；爆炸半径最小；以被引用的事实而非指令被召回 |
| L1 | 失败目录的建议条目 | 所有者，逐条 | 目录本就由所有者撰写；提案条目是一份可读的 diff |
| L2 | 路由提示（哪类任务适合哪个 Worker），以规划器会召回的记忆形式存在 | 所有者，逐条 | 复用 L0 通道；不给规划器新增代码路径 |
| L3 | 代码、提示词、策略 | 仅人类，环路之外 | 否则环路能编辑自己的护栏 |

首个版本只做 L0。L1、L2 复用同一套候选/审批流程，不增加任何新权限。

## 4. 度量

关联键已经存在：`memory.recalled` 事件带有 `runId` 与记忆 id；Run 以 `completed`/`failed`
结束，并可能带所有者的 `audit.labeled` 判定。

对每条记忆 `m`，用一个投影（不新增存储，从 Journal 重算）维护：

- `exposures`：召回过 `m` 且已到终态的 Run 数；
- `good` / `bad`：最终结局为所有者标记通过或验证通过，对比所有者标记失败或验证失败；
- `lastExposedAt`。

结局优先级：所有者标签高于系统验证，因为标签正是评估用来对照的真值（见 `audit.labeled`）。

坦率的局限，写明以免阈值被误当成证明：

- 召回与任务类型相关，只用在难任务上的记忆会显得很差。缓解：在同一意图类别、且样本足够时，
  与“未召回 `m`”的 Run 对比；样本不够就报告“数据不足”。
- 样本量小。曝光不足 5 次不做任何自动动作；排序用 Wilson 下界而非原始比例。这两个数字是保守的
  推测值，需要用所有者的真实历史调参，不是实测常数。

## 5. 生命周期规则（全部只是建议，所有者批准后才应用）

1. **90 天寿命**（已决定，已实现）。提升时没有自带过期时间的记忆，设为 `expiresAt = 现在 + 90 天`；
   提炼器自带的过期时间优先。90 天对应一个项目、一个工作周期或一个学期。另外，**任何活跃记忆如果
   90 天内既没被召回、读取也没被编辑，就会被归档**（原因 `idle`，可通过 restore 撤销；被恢复的
   记忆视为刚被使用）。陈旧是旧教训变有害的主要途径。该扫描与过期扫描一起跑在后台维护循环里。
2. **强化**：曝光足够且下界良好的教训，得到“保留”建议：延长 `expiresAt` 并提高置信度。
3. **淘汰**：结局比“未召回”基线更常变差的教训，得到附带数字的“归档”建议。
4. **取代**：与某条活跃教训重叠的新候选，与它并排展示（“替换 / 都保留 / 拒绝”）。指纹去重抓不到
   改写后的同义句，由所有者担任语义裁判。
5. **预算**：待审教训候选最多 N 条（提议 10）。候选泛滥会训练所有者盲目通过，等于废掉门禁。

## 6. 失败诊断

单次失败的教训容易对一次事故过拟合。聚类使用现有的 `FailureReport.signature`（易变细节已去除）
加类别：

- 1 次失败：只产生低置信、会过期的候选（当前行为）。
- 不同 Run 中出现 3 次及以上相同 signature：提议更高置信的教训或 L1 目录条目，并引用全部证据 id。

阈值 3 是为区分巧合与规律而设的假设，需用真实数据复核。

## 7. 安全性质

- 每一步都是 Journal 事件；`memory.archived` / `memory.restored` 已使每次变更可回滚。
- 教训经 `buildMemoryContext` 召回：只给摘要、剥掉指令措辞、secret 不外露。被投毒的教训既不能
  指挥 Worker，也带不出凭据。
- 教训改变不了授权。策略在咨询记忆之前就已决定，本设计也没有增加任何从记忆到策略的路径。
- 总开关：一个设置即可关闭教训提炼与环路；已批准记忆的召回不受影响。
- 基准（`npm run bench`）是回归门：启用一批已批准教训前后各跑一次，分数下降就是归档该批的理由。
  它规模小且用真实 Provider，所以只能当冒烟测试，不是统计结论。

## 10. 实现

```
journal（memory.recalled、run.status_changed、audit.labeled、执行失败）
   |
   v
src/improvement/analysis.ts      纯函数：每条记忆的结局、Wilson 区间、
   |                             生命周期规则、失败聚类
   v
src/improvement/improvement-service.ts
   sweep()    -> improvement.suggested   （确定性 id，待决最多 10 条）
              -> 为所有者标为 "fail" 的 Run 请求教训提炼
   approve()  -> MemoryGovernance（归档 "retired" / 更新 / 新增教训）
              -> improvement.applied
   dismiss()  -> improvement.dismissed
   ^
   |  后台维护循环（companion-server），先于闲置扫描
   |  CLI：clone-ai improve [list|stats|sweep|approve|dismiss]
   |  API：GET /api/improvement，POST /api/improvement/suggestions/:id/(approve|dismiss)
```

决定与理由：

- **分析是纯函数，服务很薄。** 每条规则都只是 Journal 的函数，无需存储即可测试，投影丢了重算即可。
- **提炼以 `runId:outcome` 为键。** 按“完成”提炼过的 Run，在所有者把它标为失败后必须能再次提炼；
  旧的按 Run 的键会把它挡住。
- **聚类得出的教训通过 `author()` 加入**，而不是作为提炼候选：聚类横跨多个 Run，而候选只能引用
  自己 Run 的证据。所有者的批准就是证据。
- **环路只改记忆**，且走受治理的路径，因此归档/恢复使每次变更都可回滚。它没有通向代码、提示词
  或策略的路径。
- **总开关：** `CLONE_AI_IMPROVEMENT=0` 停止扫描；已批准的记忆照常工作。
- **未实现：** 桌面端建议界面（目前用 CLI 或 API）、重叠记忆的取代、自动化基准门禁。
